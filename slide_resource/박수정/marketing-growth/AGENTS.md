# 그로스 마케팅 강의자료 제작 에이전트 지침

이 폴더는 **112시간 독립 과정** `course-11e227c0534d`의 기획·근거·제작 초안을 모은다. 강의자료 제작 요청에는 공용 [교안 제작 에이전트](tooling/lesson-author/SKILL.md)를 사용하고, 이 파일의 과정별 입력과 검토 기준을 함께 적용한다.

## 제작 입력

1. [과정 기획서](./과정_기획서.md)에서 대상·목표 직무·112시간·최종 프로젝트를 확인한다.
2. [교과·차시 편성](./교과_차시_편성.md)에서 요청한 M1~M6 항목과 이론·실습 시간, 학생 결과물을 특정한다. 나머지 차시를 임의로 함께 제작하지 않는다.
3. [NCS 선택](./NCS_선정_기록.md), [근거 목록](./evidence/근거_목록.md), [근거 중심 학습서](./evidence/근거_중심_학습서.md)를 읽고 해당 주장마다 원문 위치를 적는다. NCS 원문은 [공식 검색 경로](references/NCS.md)에서, REF 문서는 [참고 자료](references/INDEX.md)에서 확인한다.
4. [가상 입력 데이터](evidence/multimodal-assets/README.md)와 [112시간 워크북](./evidence/112h-workbook/112시간_실습_워크북.md)을 사용할 때 실측 자료와 구분한다. 관찰 캠페인 데이터, 무작위 배정 예시, 서로 다른 광고 소재를 하나의 인과 실험으로 합치지 않는다.

## 초안 작성과 검토

- 과정의 정식 차시 제작 초안은 이 폴더의 `lesson-drafts/<차시-ID>/`에 둔다. 팀 과제의 10분 시강 초안은 아래 인계 규칙에 따라 `team-agents/결과/02_교안/`에 둔다. 두 경우 모두 공용 에이전트 계약의 `lesson.json`, `evidence.md`, `lesson.md`, `practice.md`, `review.md`를 만들고 강사용 해설과 학생용 지시를 분리한다.
- 완성 교안의 재사용 판단은 현재 모두 `new`다. 기존 CSV·이미지·영상·음성을 실습 **입력 파일**로 쓰는 6개 활동도 교안과 지시서는 새로 작성한다.
- GA4·Looker Studio·광고 계정·유료 AI 기능의 실제 접근 권한은 확인 전이다. 화면·기능·수치를 확인하지 못하면 강사 검토 항목으로 남기고 합성 데이터 대체 경로를 적는다.
- 생성 후 저장소 루트에서 `node tooling/lesson-author/scripts/validate.mjs lesson-drafts/<차시-ID> --with-slides`로 구조와 HTML·PDF를 검사한다. 출처·시간·실습 실행 가능성은 강사가 별도로 검토한다.
- 초안 파일만 작성한다. Instructor Studio는 이 공개 저장소에 포함되지 않는다. 원래 작업 공간에서 과정 데이터·교안 연결·확정본을 바꿀 때에는 강사가 검토 후 명시적으로 저장해야 하며, 최신 revision과 단계 상태를 직접 조회한다. [Studio 적용 기록](./LMS_적용_기록_2026-11-18.md)의 revision은 당시 이력이다.

## 팀 공동 작업과 인계

[팀 공유 브리프](team-agents/공유_브리프.md)에 확정된 결정과 제안·미확인 조건을 구분한다. 팀 리더가 합의 내용을 반영하고 세 담당자는 같은 버전을 읽는다. 팀 과제의 세부 절차는 [실행 순서](team-agents/실행_순서.md)에 둔다. 아래 파일은 `team-agents/결과/`에 작성하며, 다른 담당자의 결과를 덮어쓰지 않는다.

| 담당 | 역할 | 소유 결과 |
|---|---|---|
| 1번 | 실제 제안·수강생 문제·근거·학습 요구 | `01_근거와_목표.md` |
| 2번 | 전략·커리큘럼 연결과 교안 초안 | `02_설계_요약.md`, `02_교안/`의 계약 파일 5개 |
| 3번 | 시강 덱·검증과 제작 과정 발표 근거 | `03_시강.html`, `03_시강.pdf`, `03_검토.md`, `03_발표_근거.md` |

- 1번은 REF-031 원문 사실, 이번 과정의 설계값, 실제 수강생에 관한 가정을 분리한다. 출처 위치·미결정 사항·다음 담당자가 확인할 내용을 기록한다.
- 2번은 1번의 학습 요구와 과정의 교과·목차를 연결한다. `lesson.json` 시간 합계가 팀이 확인한 시강 시간과 맞는지 검사하고, `lesson-author` 구조 검사를 통과한 뒤 넘긴다.
- 3번은 HTML·PDF를 열어 흐름·글자 잘림·출처를 확인한다. 발표 주장을 실제 결과 파일에 연결하고, 리허설 전이면 소요 시간을 `미실행`으로 표시한다.
- 각 담당자는 자신이 확인한 것과 남은 질문, 사람이 수정한 이유를 남긴다. 팀 결과도 강사 검토 전 초안이며, 위의 과정 저장 원칙을 따른다.
