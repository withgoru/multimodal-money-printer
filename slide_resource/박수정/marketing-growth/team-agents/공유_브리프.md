# 공유 브리프

> 세 에이전트가 같은 입력을 읽는 문서다. **확정된 팀 결정**과 **개인 제안·미확인 조건**을 구분한다. 팀 회의에서 정해진 항목만 갱신한다.

| 항목 | 현재 입력 | 상태 |
|---|---|---|
| 과제 | 각자의 코딩 에이전트로 실제 강의 제안을 분석하고 학습 요구·강의 전략·커리큘럼·교안 초안을 연결해 제작 과정을 발표 | 과제 방향 |
| 새 수업 분야 | 마케팅·데이터 분석 | 팀 합의 |
| 분석 사례 | [고용24 REF-031](../references/REF-031_멀티모달AI_풀퍼널마케팅.md)과 [112시간 독립 과정 기획서](../과정_기획서.md) | 원 제안의 편성과 이번 설계값을 구분해 발표 |
| 과정 설계 입력 | [단계별 산출물 지도](../진행_현황.md)의 NCS·근거·교과·실습 자료 | 기존 과정 자료를 팀의 한 차시 설계에 연결. 공식 신청·강사 검토 전 |
| 수강생 문제 | 초급 학습자가 캠페인 목표와 광고 지표를 연결하고, 관찰된 성과와 효과·한계를 구분해 다음 행동을 제안해야 한다 | 설계 가정. 실제 수강생 조사·수준 진단 전 |
| 10분 시강 세부 주제 | “클릭률이 높은 광고가 구매 목표에도 더 좋은가?” | 팀 선택 전 제안 |
| 10분 학습자·목표·증거 | 예비·초급 마케터가 가상 결과표에서 목표에 맞는 지표를 계산·비교하고, 우선 검토할 캠페인과 판단 한계를 한 문장으로 설명한다 | 시강 제안. 팀 확정 전 |
| 시강 조건 | 10분 시강과 제작 과정 발표는 별도 자료로 준비한다. 계정·광고비 없이 가상 결과표로 시연할 수 있다 | 시간·제출 조건은 과제 원문 재확인, 대체 시연은 제안 |
| 교안 제작 방식 | [lesson-author 스킬](../tooling/lesson-author/SKILL.md)로 `lesson.json`과 근거·강사용 교안·학생 실습·검토 기록을 초안으로 만든다 | 스킬 구현 완료. 이번 마케팅 차시 실행 전 |

## 팀 회의에서 확정할 것

1. 과제 원문의 시강·발표 시간, 공동 교안 수, 제출 형식과 기한.
2. 10분 시강의 세부 주제, 실제 학습자 수준, 확인 가능한 행동과 답.
3. 기존 112시간 과정 설계에서 시강에 가져올 범위와 사용 가능한 실습 데이터·도구.
4. 세 결과의 담당자, 인계 시각, 리허설·피드백 기록 방식.

기존 [AI 답변 근거 확인 예시](../tooling/lesson-author/examples/grounded-answer/lesson.md)는 에이전트 구조를 설명할 때만 사용한다. 이번 마케팅 수업의 근거와 학생 과제는 1번의 검토 결과에 따라 새로 작성한다.
