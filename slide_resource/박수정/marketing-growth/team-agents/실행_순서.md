# 실제 강의 제안에서 교안·발표까지 인계하기

## 0. 팀 합의 — 10분

세 사람이 [공유 브리프](./공유_브리프.md)의 **마케팅·데이터 분석 분야, 세부 주제, 학습자, 시강 시간과 목표, 확인 증거**를 검토한다. 현재 세부 주제와 학습자 수준은 제안이므로 팀이 합의한 뒤 팀 리더가 브리프를 수정해 같은 Git 커밋을 전달한다. 과제에서 정한 시간·제출물은 원문으로 확인한다.

## 1. 세 에이전트 실행

각 팀원은 자기 코딩 에이전트를 같은 저장소의 **서로 다른 브랜치 또는 작업 복사본**에서 실행한다. 역할 파일 전체를 에이전트에 붙여 넣고 해당 파일의 출력만 맡긴다. 서로 같은 파일을 동시에 고치지 않는다.

처음에는 1번이 REF-031과 과정 기획의 근거를 확인하고, 2번이 기존 교과·목차 설계를 읽으며, 3번이 슬라이드 템플릿과 PDF 출력 환경을 준비할 수 있다. 최종 내용은 **1번의 제안·학습 요구 → 2번의 전략·교안 → 3번의 시강 덱·발표 근거** 순으로 인계한다. 확인 전 내용을 완료 결과로 표시하지 않는다.

| 순서 | 사람과 에이전트 | 받는 파일 | 만드는 파일 | 팀원이 확인할 것 |
|---|---|---|---|---|
| 1 | 1번: 제안·학습 요구 | 공유 브리프, REF-031, 과정 기획·근거 | `01_근거와_목표.md` | 원문 사실과 수강생 가정의 구분, 학습 요구·출처·미결정 사항 |
| 2 | 2번: 전략·교안 에이전트 | 1번 커밋, 기존 교과·목차, `lesson-author` | `02_설계_요약.md`, `02_교안/` 파일 5개 | 전략 → 교과 → 차시 연결, 시간 합계, 학습자 행동·대체 시연 |
| 3 | 3번: 덱·검증 | 1·2번 커밋 | `03_시강.html`·`.pdf`, `03_검토.md`, `03_발표_근거.md` | 글자 잘림·출처·실제 시강 시간, 과정 발표의 주장과 결과 파일 일치 |

**인계 문장 예시:** “1번 결과를 `abc1234` 커밋에 올렸습니다. 목표 제안은 ‘구매 목표에 맞는 지표를 비교하고 판단 한계를 설명’이며, 출처와 아직 확인하지 못한 학습자 수준은 문서 마지막에 있습니다.”

각자가 브랜치에 결과 파일을 커밋한 뒤 팀 리더가 순서대로 합친다. 예: `git add 결과/01_근거와_목표.md` → `git commit -m 'Draft proposal analysis and learning needs'`. 2번은 합쳐진 1번 결과를 읽고 자기 설계·교안을 수정한 뒤 인계한다. 3번도 같은 방식으로 1·2번 최종본을 읽는다.

## 2. 합치기와 발표 증거

1. 팀 리더가 세 결과를 하나의 브랜치에 모으고 파일 끝의 `남은 질문`을 함께 처리한다.
2. 각자 자기 에이전트의 **입력 지시문 → 생성한 파일 → 사람이 고친 부분**을 1분 이내로 보여 줄 수 있게 준비한다. 2번은 [교안 에이전트의 모듈 구조](../tooling/lesson-author/ARCHITECTURE.md)를 설명할 수 있다. Git diff나 커밋이 증거다.
3. 조별 발표에서는 1번이 실제 제안과 학습 요구, 2번이 전략·커리큘럼·교안, 3번이 시강 덱·검증을 설명한다. 3번은 `03_발표_근거.md`에 각 주장과 실제 파일을 연결하고, 세 사람이 함께 수정한 결정 한 가지를 보여 준다.
4. 시강은 `03_시강.html`로 진행한다. [기존 제작 과정 발표덱](../references/PROJECT-SOURCES.md)과 시강용 강의덱은 목적이 다르므로 구분한다. 기존 발표덱의 AI 답변 예시는 팀의 마케팅 시강이 완료됐다는 증거로 쓰지 않는다.

## 3. 회의 준비 완료 기준

회의 준비는 **실제 제안 분석 → 수강생 문제·학습 요구 → 강의 전략·커리큘럼 연결**까지의 검토 자료가 있으면 완료로 판정한다. [과정 기획서](../과정_기획서.md)에 제안 근거·학습 대상 가정·목표와 학습 순서를, [교과·차시 편성](../교과_차시_편성.md)에 6개 교과·23개 활동·학생 산출물의 연결을 기록했다. [공유 브리프](./공유_브리프.md)는 회의에서 확인할 수강생 문제와 미결정 조건을 구분한다.

**현재 판정: 회의 준비 완료.** 세부 주제·학습자 수준·시강 조건은 회의에서 결정한다. 아래 교안 작성·검수·최종본, 시강·발표 제작은 회의 이후의 실행 단계다.

## 4. 시강·발표 실행 완료 기준

- 세 담당자의 결과 묶음에 입력 근거와 인계 내용이 있다.
- 교안 시간표가 과제에서 확인한 시강 시간에 맞고 실제 리허설에서 그 안에 끝난다.
- 학생에게 한 가지 행동을 시키고 결과를 확인한다.
- 실패 시연의 대안이 있다.
- HTML과 PDF를 모두 열어 확인했다.
- 실제 제안의 사실과 학습자 가정, 기존 과정 설계와 이번 시강 교안의 관계가 발표에서 구분된다.

현재 저장된 [기존 발표덱](../references/PROJECT-SOURCES.md)은 **제작 절차를 설명하는 자료**다. `결과/03_시강.html`은 팀원 3번의 에이전트가 만들 **이번 마케팅 수업의 강의덱**이며 아직 없다.
