# 멀티모달 AI 데이터 기반그로스 마케팅 · S5 실습·데모 설계 초안

작성일: 2026-11-18<br>
대상 과정: `course-11e227c0534d` · 작성 기준 revision 9 · Studio 반영 후 revision 62<br>
상태: **23개 실습과 로컬 강사 데모 3단계의 Git 기준점을 Studio에 저장. S5는 26/26.** 실제 클라우드 공개·광고 집행은 검증되지 않았다. M3-4의 R3 유의값 해석 추가는 강사 검토용 파일 초안이며 Studio 실습에는 아직 적용되지 않았다.

## 설계 기준

- [112시간 과정 기획서](./과정_기획서.md)의 최종 산출물은 다음 캠페인 집행·예산 제안서다. [편성 목차](./교과_차시_편성.md)의 실습 항목 23개, 실습 74시간을 그대로 사용한다. 아래 수행 단계는 [112시간 워크북](./evidence/112h-workbook/112시간_실습_워크북.md)의 동명 항목을 학생 행동으로 옮긴 제안이다. 차시 교안·슬라이드·채점 해설을 확정한 것이 아니다.
- 입력 R1~R7은 모두 교육용 가상 자료다. [데이터 설명](./evidence/112h-workbook/가상_데이터_설명.md)의 행 단위와 경계를 매 차시 시작에 확인한다. R1/R4 관찰, R3/R6 가상 배정, R7 예측을 하나의 실측 캠페인이나 동일 고객군의 연속 기록으로 합치지 않는다. R2의 두 소재는 여러 요소가 동시에 달라 단일 변수 실험에 직접 쓰지 않는다.
- 기본 환경은 CSV를 열고 집계할 수 있는 스프레드시트 또는 동등한 로컬 도구, 워크북, 근거 목록이다. GA4·Looker Studio·광고 플랫폼·유료 AI 계정은 **선택 경로**다. 강사가 권한과 최신 화면을 확인하기 전에는 구체 메뉴 경로를 학생 지시로 고정하지 않는다. 계정이 없을 때도 표·차트·검산표를 로컬에서 완성한다.
- 각 실습의 완료 증거는 **원본 이름·행 단위·필터·분자/분모·기간·계산식·해석 한계**를 따라갈 수 있어야 한다. 표에 적힌 산출물은 같은 최종 제안서로 이어지는 중간 산출물이며 별도 프로젝트 시간을 더하지 않는다.

### 공통 진행·확인 방식

1. 강사는 입력 파일의 가상 자료 표시, 행 단위, 실습 목표와 제출 증거를 보여 준다. 숫자 하나의 재계산 또는 오류 사례 하나를 시연한다.
2. 학생은 원본을 보존한 작업 사본에서 수행 단계를 실행하고, 계산 표 또는 의사결정 문서에 사용한 규칙을 남긴다.
3. 학생은 다른 사람이 주요 수치 하나를 재현할 수 있게 원천 행·필터·식의 위치를 제출한다. 값이 맞아도 자료 범위를 넘는 인과·일반화 주장은 수정한다.
4. 강사는 **원천 대조 가능성, 지표 정의의 일관성, 누락·오류 처리, 관찰/실험/예측/가정 구분**을 확인한다. 점수·배점과 NCS 수행준거별 채점표는 S7 평가 설계에서 확정한다.

M3-4의 **R3 유의값 해석 추가 부분은 강사 검토용 수정 초안**이다. Studio에 이미 저장된 M3-4 실습에는 아직 반영되지 않았으며, 검토 후 해당 실습을 선택해 저장해야 한다.

## 강사 데모 3단계 초안

Studio의 S5는 `build / automate / deploy` 세 단계를 요구한다. 이 과정의 최종 결과는 앱 개발이 아니라 **근거를 추적할 수 있는 마케팅 집행 제안**이므로, 각 단계의 종료 상태를 분석 작업물과 공유·검토 가능한 결과로 정의한다. 로컬 [강사 데모](./s5-demo/README.md)의 Git 커밋 3개는 확인했다. 실제 클라우드 공개나 광고 집행은 수업 성취로 간주하지 않으며 공개 URL도 없다.

| 단계 | 강사가 시연할 시작→종료 상태 | 학생의 독립 과제·증거 | 실패 시 대체 경로·미확인 항목 |
|---|---|---|---|
| **build · M1~M3** | 별도 R4/R5 원본에서 행 단위·누락·중복을 확인하고 지표 정의·원천 대조가 붙은 성과 표와 차트를 완성한다. | 자기 가상 사례의 KPI 표, 데이터 품질 기록, 검산 가능한 차트 1개. | Looker Studio 연결이 안 되면 로컬 스프레드시트 차트. 로컬 데모 Git 기준점은 `22e83ac`다. |
| **automate · M4~M5** | R6의 AI 요약 또는 가상 AI 문장을 원천과 대조하고, R7 기준/비교 모델 및 가정별 예산표로 이어 간다. 자동 제안의 수용·수정·폐기를 눈앞에서 기록한다. | AI 검토표, 실험 효과·구간, 모델 검증표, 민감도 표. | 유료 AI 접근이 없으면 가상 AI 문장 3개와 수동 검산. 로컬 데모 Git 기준점은 `38164e0`이다. |
| **deploy · M6** | 최종 집행 제안서를 검토자가 원천 수치까지 따라갈 수 있는 공유용 PDF 또는 읽기 전용 문서로 내보내고, 공개 범위·데이터 사용권·재현 가능성을 점검한다. | 제안서와 재계산 기록, 반론·수정 이력, 공유본의 접근 점검표. | 공개 권한이 없으면 로컬 PDF와 상대 경로 자료 묶음. 실제 광고 계정 집행·클라우드 URL은 강사와 기관의 별도 결정·검증이 필요. |

**Studio S5 적합성:** 현재 [Studio 플로우 구현](references/PROJECT-SOURCES.md)의 데모 라벨은 `서비스 구축 / AI·RPA 업무 흐름 통합 / 클라우드 배포·운영`이며, 각 단계의 `studentTask`, `evidence`, **실제 Git 기준점**을 요구한다. 로컬 [강사 데모](./s5-demo/README.md)의 세 Git 기준점이 연결돼 Studio 계산상 S5는 26/26이다. 이 과정의 `deploy`는 검토용 로컬 보고서 제공까지이며, 공유용 PDF나 로컬 서버를 실제 클라우드 배포·운영 성취로 표시할 수 없다. 기관의 실제 클라우드 성취 요구 여부는 별도 결정 사항이다.

**데모 준비 상태:** 단계 정의와 로컬 Git commit/ref, 재현 명령은 Studio에 저장됐다. 실제 공개 데모 URL, 클라우드 계정·권한, 광고 집행과 배포 검증은 **미확인**이다. Studio의 `deploy` 단계도 `verified: false`다. 파일 공개가 결정되면 합성 데이터만 포함하고 실제 고객 정보·비밀 값이 없는지 확인한다.

## 강사 검토·적용 전 확인

1. R1~R7 파일을 수업 환경에서 열 수 있는지와 각 차시의 시간 안에 계산·피드백이 가능한지 시범 실행한다. 워크북의 예시 수치와 학생 제출 양식을 한 번 대조한다.
2. M2의 GA4/Looker Studio와 M4의 광고 플랫폼 실습은 실제 계정·권한·최신 메뉴를 확인한 경우에만 화면 조작을 추가한다. 확인 전 학생 기본 경로는 합성 CSV다.
3. NCS M1·M3·M6의 수행준거별 채점 증거와 배점은 [원문 위치가 있는 선정 기록](./NCS_선정_기록.md)을 바탕으로 S7에서 정한다. 이 파일의 확인 기준은 채점 해설이 아니다.
4. 사용자의 “S5 진행하자” 지시로 실습 23개와 목차 `practiceId`, 데모 계획을 Studio revision 62까지 저장했다. 이후 [로컬 강사 데모](./s5-demo/README.md)의 세 Git 기준점이 연결되어 revision 71 조회에서 플로우는 **26/26**이다. `validate_course`의 오류는 0건이다. 실제 클라우드 배포와 광고 집행은 이 판정에 포함되지 않는다.
