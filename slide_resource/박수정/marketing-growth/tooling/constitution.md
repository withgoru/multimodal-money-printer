# Project Constitution

> KDT 강의 교안 제작의 불변 작업 원칙. 설계·구현·검증 전에 읽는다.

## 1. 프로젝트 원칙

### P-001. 강사 검토 후 적용

AI가 만든 편성·목차·실습·평가·운영표·교안은 먼저 초안으로 보인다. 과정 데이터의 저장과 기존 자료 교체는 강사의 명시적 적용·저장 동작에서만 수행한다. 교안 CLI도 `lesson-drafts/`까지만 작성한다.

### P-002. 근거와 확인 상태

NCS·기존 자료를 인용할 때 원문 위치와 연결을 보존한다. 자동 검사는 사실성의 확정 판정으로 표시하지 않으며, 확인되지 않은 화면·명령·수치는 강사의 검토 항목으로 남긴다.

### P-003. 과정 격리와 충돌 방지

과정별 기획서·교과·교안·확정본을 과정 ID별로 관리한다. 쓰기 작업은 최신 revision을 확인해 동시 수정 충돌을 드러낸다. 여러 과정 중 하나를 암묵적으로 선택하지 않는다.

### P-004. 강사용 정보와 학생용 자료 분리

채점 해설·검토 지시·미확인 사항 등 강사용 정보는 학생에게 배포하는 본문과 구분한다. 배포용 묶음은 실제 포함한 자료에만 연결한다.

### P-005. 인터페이스와 검증

화면과 도메인·API 경계 변경은 `docs/specs/v0.2.0/003-kdt-course-flow/plan.md` 및 `004-course-autopilot/plan.md`의 인터페이스 계약을 먼저 확인한다. TypeScript 검사와 관련 테스트를 통과시키고, 생성 PDF의 검토 쪽수는 실제 PDF 범위에 맞춘다.

## 2. 변경 원칙

이 원칙을 바꿔야 할 때에는 근거와 영향을 문서화하고 사용자 결정을 반영한다. 환경 구성과 현재 구현 상태는 각각 `infra.md`, `context.md`에 기록한다.
