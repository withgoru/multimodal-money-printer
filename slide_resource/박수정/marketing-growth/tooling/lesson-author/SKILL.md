# 교안 제작 에이전트

다른 강사도 검토하고 수정해 수업에 쓸 수 있는 교안 초안을 만든다. 자료에서 확인한 사실과 사용자가 정한 조건을 구분한다. 검토 전 초안은 확정된 과정 데이터와 분리한다.

## 시작 절차

1. 사용자 요청과 제공된 과정 자료를 읽는다. 주제·학습자·수업 시간·학생이 할 행동이 빠졌다면 자료에서 뒷받침되는 범위만 추론하고 `review.md`에 가정으로 표시한다. 선택에 따라 수업이 달라지면 사용자에게 묻는다.
2. 작업할 단계의 [모듈 안내](references/modules.md)와 [산출물 계약](references/artifact-contract.md)을 읽는다. 이 저장소의 Instructor Studio 과정과 연결할 때만 [KDT 연결 규칙](references/kdt-adapter.md)을 적용한다.
3. 새 출력 폴더에 `lesson.json`, `evidence.md`, `lesson.md`, `practice.md`, `review.md`를 작성한다. 사용자가 **전체 교안을 만들어 달라**고 하면 별도 형식 지시가 없어도 같은 차시의 발표 자료 `lesson.html`, `lesson.pdf`를 만든다. `lesson.pptx`는 사용자가 PPTX·PowerPoint 형식을 명시적으로 요청한 경우에만 만든다. 차시 설계·목차 작성·기존 파일의 부분 수정 요청에는 발표 자료를 자동으로 추가하지 않는다. 사용자가 출력 형식을 지정하면 그 지시를 따른다. 이 프로젝트의 HTML·PDF 발표 자료에는 기존 슬라이드 템플릿을 적용한다.
4. 스킬 폴더에서 `node scripts/validate.mjs <출력 폴더>`를 실행한다. HTML·PDF를 만들었으면 `--with-slides`, PPTX도 만들었으면 `--with-pptx`를 추가해 해당 파일을 검사한다. 구조 오류를 고친 뒤 생성한 각 형식을 실제로 열어 같은 차시 내용과 페이지 순서, 글자 잘림을 확인하고, 스크립트로 판단할 수 없는 출처의 정확성과 수업 적합성을 강사 관점에서 확인한다.
5. 초안과 남은 질문을 강사에게 보여 준다. 강사가 채택할 내용을 고르기 전에는 Instructor Studio에 저장하거나 반영·확정 동작을 실행하지 않는다.

## 모듈

| 모듈 | 판단할 내용 | 필수 결과 |
|---|---|---|
| 입력 정리 | 학습자·목표·시간·환경·제약 | `lesson.json`의 수업 정보 |
| 근거 확인 | 어떤 내용에 확인 가능한 출처가 있는가 | `evidence.md`, `lesson.json`의 출처 |
| 차시 설계 | 목표 → 확인 증거 → 활동 → 설명 | `lesson.json`의 수업 구간 |
| 교안 작성 | 강사 행동·학생 행동·실습·대체 시연 | `lesson.md`, `practice.md` |
| 검토 | 시간·출처·실행 가능성·남은 결정 | `review.md` |

요청에 필요한 모듈만 실행한다. 수정할 때는 이미 채택된 내용을 보존하고, 영향을 받은 모듈과 검증을 다시 실행한다. 출처로 뒷받침되지 않는 주장은 수업 내용에 사실로 넣지 않고 `review.md`에 확인할 질문으로 남긴다.
