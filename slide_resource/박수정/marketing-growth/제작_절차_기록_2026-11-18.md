# 멀티모달 AI 데이터 기반그로스 마케팅 · 강의자료 제작 과정 메모

기록일: 2026-11-18

목적: 팀원이 이번 사례를 따라 **무엇을 AI에게 맡기고, 무엇을 강사가 확인·채택·저장하는지** 볼 수 있게 작업 순서와 지시 방식을 남긴다. 아래의 ‘재현용 지시 예시’는 같은 작업을 다시 요청할 때 쓸 수 있는 문장이지, 과거 대화의 원문 기록은 아니다.

## 현재 기준점

- **채택한 주제:** 멀티모달 AI 데이터 기반그로스 마케팅. 사용자가 제시한 [7개 커리큘럼 항목](./NCS_선정_기록.md#1-채택한-커리큘럼)을 내용 기준으로 삼는다.
- **운영 범위:** 사용자가 **112시간 독립 과정**으로 결정했다. [고용24 REF-031](references/REF-031_멀티모달AI_풀퍼널마케팅.md)의 전체 800시간 중 동명 교과 112시간은 시간·내용의 참고 사례다. 참고 과정의 원래 편성은 NCS 미적용이다.
- **현재 산출물:** [단계별 지도](./진행_현황.md), [과정별 NCS 선택표](./MARKETING_GROWTH_NCS_SELECTION_2026-11-18.xlsx), [근거 목록](./evidence/근거_목록.md), [과정 기획서 초안](./과정_기획서.md), [5단계 파일 기반 편성 초안](./교과_차시_편성.md), [S5 실습·데모 설계 초안](./실습_데모_설계.md), [Studio 적용 기록](./LMS_적용_기록_2026-11-18.md), [M1-1-P 차시 초안](./lesson-drafts/M1-1-P/lesson.md). [근거 중심 학습서](./evidence/근거_중심_학습서.md)와 멀티모달 데이터 팩도 있으나, 강의 슬라이드나 차시 교안의 확정본은 아니다.
- **Studio 저장 상태:** `course-11e227c0534d`에 112시간 교과 6개, 이론·실습 목차 46개와 자료 판단을 저장했다. S0~S4는 `done`이며 S5는 실습 23개와 로컬 데모의 Git 기준점 3개를 연결해 **26/26**이다. 실제 클라우드 공개는 검증되지 않았다.

## 실제 사용 사례 · M1-1-P 차시 초안

이 사례는 파일과 Git 커밋 `116eff3`으로 확인되는 **차시 초안 제작 결과**다. 생성 당시의 원문 프롬프트나 에이전트 호출 기록은 이 폴더에 없으므로 특정 지시문을 실제 입력으로 단정하지 않는다.

1. **입력 범위:** [교과·차시 편성](./교과_차시_편성.md)의 M1-1 실습 1시간과 [112시간 워크북](./evidence/112h-workbook/112시간_실습_워크북.md)의 해당 활동을 사용했다. 근거는 합성 R1 캠페인 CSV, NCS 마케팅 성과 관리 PDF 73쪽을 포함한 3개 출처로 [출처 기록](./lesson-drafts/M1-1-P/evidence.md)에 연결했다.
2. **초안 생성:** `lesson-drafts/M1-1-P/`에 [시간표 JSON](./lesson-drafts/M1-1-P/lesson.json), [출처 기록](./lesson-drafts/M1-1-P/evidence.md), [강사용 진행 원고](./lesson-drafts/M1-1-P/lesson.md), [학생 실습서](./lesson-drafts/M1-1-P/practice.md), [검토 기록](./lesson-drafts/M1-1-P/review.md)을 분리했다. 강사가 시연하고 학생이 KPI 분자·분모와 부족한 데이터를 표시한 뒤 제출물을 확인하도록 60분을 5개 구간으로 나눴다.
3. **검증과 인계:** `node agents/lesson-author/scripts/validate.mjs marketing-growth/lesson-drafts/M1-1-P` 구조 검사는 **60분·출처 3개·구간 5개**로 통과했다. 이 검사는 원문 사실성이나 실제 60분 수업 가능성을 확정하지 않는다. [검토 기록](./lesson-drafts/M1-1-P/review.md)에 학습자 선수지식, 스프레드시트 환경, 실제 소요 시간과 NCS 채점 기준의 확인 사항을 남겼다. 강사 검토·Studio 교안 저장·발표 자료 제작은 아직 완료되지 않았다.

PDF 이동 뒤 바뀐 근거 ID의 재색인·재연결과 확인 결과는 [Studio 적용 기록](./LMS_적용_기록_2026-11-18.md)에 남겼다. 이 구조 설명은 현재 파일 역할을 기록한 것이며, 확인되지 않은 과거 작업 순서를 완성된 연혁으로 표시하지 않는다.

## 팀원이 AI에게 줄 수 있는 지시 예시

아래 문장은 **재현용 예시**다. 매 단계에서 채택 범위와 저장 여부를 함께 말하면 결과를 검토하기 쉽다.

1. **레퍼런스:** “고용24 공개 과정 중 AI/AX, 마케팅, 데이터 분석 교과가 모두 확인되는 후보를 찾아 줘. 과정 ID·원문 링크·교과 시간·기존 REF 중복을 대조하고 채택 후보와 비교 자료를 나눠 줘.”
2. **NCS:** “채택한 7개 항목을 유지하면서 마케팅전략기획·고객관리 NCS PDF의 수행준거와 쪽수에 연결해 줘. 선택·제외 이유와 비 NCS 범위를 따로 적고, 과정별 선택표에서 시간 합계를 검산해 줘.”

## 이 대화에서 확인된 지시와 그 영향

- 사용자는 채택한 주제가 [산출물 지도](./진행_현황.md)에서 미정처럼 보인다고 지적했다. 지도에 **주제와 7개 항목 채택 완료**를 명시하고, REF-031 채택을 다시 결정하라는 문구를 정리했다.
- 사용자는 과정 기획서가 있는지 확인했다. 파일 초안의 존재와 **강사 검토가 필요한 112시간 편성** 상태를 확인했다. 이후 **112시간 독립 과정**으로 운영하기로 결정했다.
- 사용자는 **“교과 시간 → 교안 목차 → 재사용·신규 제작 판단” 순서의 계획**을 요청하면서 그 단계에서 자료를 직접 생성하지 말라고 했다. 이에 단계별 에이전트 보조를 우선하고 오토파일럿은 후속 선택지로 두는 실행 계획만 제시했다.
- [5단계 파일 기반 편성 초안](./교과_차시_편성.md)은 별도 작업에서 작성됐다. 앞선 ‘계획만’ 요청에는 계획만 제시했고, 현재 파일에는 6개 교과·23개 목차·자료 판단이 기록돼 있다.
- 사용자가 **“남은일 처리”**를 지시한 뒤 별도 마케팅 Studio 과정에 기획서·교과·목차·자료 결정을 저장했다. [적용 기록](./LMS_적용_기록_2026-11-18.md)에 과정 ID, 시간 검산, S0~S4 상태를 남겼다.
- 사용자가 **“실습 설계 들어가자”**라고 지시했다. 이에 23개 실습 차시와 3단계 데모를 [검토용 파일 초안](./실습_데모_설계.md)으로 구체화했다. 이어 **“S5 진행하자”**라는 적용 지시를 받아 Studio에 실습 23개·목차 연결·데모 계획을 저장했다. 당시 Git 기준점이 없어 S5는 23/26이었다. 이후 [로컬 강사 데모](./s5-demo/README.md)의 커밋 3개를 연결해 26/26으로 표시됐다.
- 사용자는 강의자료 제작 에이전트 지침을 포함한 그로스 마케팅 자료를 KDT 최상위의 `marketing-growth/`로 옮겨 정리하도록 요청했다. 현재 폴더 역할과 호환 링크는 위의 정리 결과에서 확인할 수 있다.
- [M1-1-P의 파일 초안](./lesson-drafts/M1-1-P/review.md)은 실제로 존재하고 구조 검사를 통과했다. 팀원 3명의 지시문은 아직 실행 결과가 없으므로 시강·발표를 완료했다고 기록하지 않는다.
- 이 메모는 시스템을 팀원과 공유하려는 요청에 따라 작성했다. 위 1~4단계를 시작하게 한 과거 지시의 정확한 문장은 이 대화 기록에서 확인되지 않으므로 ‘재현용 지시 예시’를 원문 인용으로 읽지 않는다.

## 다음 실행 때의 경계

- [Constitution](tooling/constitution.md)의 원칙대로 AI 편성·목차·자료 판단은 먼저 **검토용 초안**으로 보여 준다. 강사가 확인한 것만 과정에 저장한다. 쓰기 전에는 대상 `courseId`와 최신 `revision`을 확인한다.
- [표준 플로우](references/PROJECT-SOURCES.md)에서 S2는 교과·총시간·NCS 근거·평가 증거, S3는 교과별 목차 시간 합계, S4는 모든 항목의 자료 결정으로 판정한다.
- 현재 Studio 플로우는 S5 26/26이다. 로컬 데모의 실제 클라우드 공개 범위는 별도 검토 사항이다. R1~R3과 새로 만든 R4~R7 가상 데이터를 차시 목적에 맞게 나눠 쓰고, 서로 다른 사례를 하나의 실제 캠페인으로 합치지 않는다. Studio의 46개 교안 목차는 `new`로 저장돼 있다. M1-1-P 파일 초안은 있으나 강사 검토·Studio 저장 전이며, 나머지 차시 교안과 발표 자료 제작은 S6에서 진행한다.
- 오토파일럿은 S0~S2 완료 후 S3~S8을 한꺼번에 작업본에 생성한다. 이번에 원하는 S2~S4만 구체화할 때는 단계별 편성·목차 추천·자료 후보 검토가 적합하다. 이후 오토파일럿을 쓴다면 실제 과정 반영 전 검토 화면에서 확인한다. 배포 환경에서는 오토파일럿이 501로 차단되어 [로컬 Studio](references/PROJECT-SOURCES.md)에서만 실행할 수 있다.
- 현재 기획서의 6개 교과에는 별도 `project` 교과가 없다. 최종 프로젝트 작업은 각 교과의 실기시간에 포함된 설계이므로, 나중에 별도 프로젝트 교과·과제서가 필요하면 시간 중복 없이 편성안을 다시 검토한다.
